# 1.4.0 (the release candidate) against 1.3.0, before the release

Measured 2026-11-24 on the Windows PC, 7 interleaved runs, every window `--behind`,
`--no-session`, a fresh scratch settings folder (`MDEDIT_SETTINGS`) for every start. A is the tag
`v1.3.0` (`ebe939d`); B is `44551a0`, `main` at `2f8399b` with `fix/restore-scroll-clamp`
merged (not pushed). Both are release builds of their own worktrees.

The script was `tools/compare-builds.py` with two changes, kept outside the repository: every
start gets its own empty settings folder (the method in `docs/CODE.md`; the tool itself sets
none), and a fourth start per run, `--exit-after-ms 6500`, gives the idle CPU as the trace's
`cpu time exit` minus its `cpu time idle`.

**Verdict.** No budget moved beyond the ranges. Memory is a little lower in B (0.5 MiB on
`sample.rs`, 1.8 MiB on `sample.md`, outside A's range on both). `sample.md` is still over the
first-frame and memory budgets, as in 1.3.0 and 1.2.1. Nothing new on the launch path.

- **Idle CPU.** 0 or 15.6 ms in each 6.4 s, one tick of Windows' clock, in both builds alike.
  Both drew 13 frames in that time in every run: the caret's blink, which runs in a window
  that is behind and has no focus.
- **The launch path.** The trace's stages are the same in both, to within a millisecond or two
  (medians, `sample.rs`, A / B): event loop 12.7 / 13.1 ms, window created 22.1 / 22.5, first
  colours 57.4 / 59.1, window shown 85.1 / 85.0. In the code, `App::new` gains only `None`
  fields for the new cards (task, note, import); no thread, file or dependency is added at start.
  The scroll fix (`view::geom`, `wrap::lowest_full_top`) works once, at the first layout after a
  restored session with word wrap on; these runs have no session, so they do not exercise it.
- **Dependencies.** No new crate. `Cargo.lock` moves the shared crates' pin (`09c67cd` and
  `49de4ec` to `ef88814`) and two patch versions (`regex-automata` 0.4.18 to 0.4.19,
  `regex-syntax` 0.8.11 to 0.8.12).
- **The exe.** `mdedit.exe` 9,194,496 bytes in A, 9,590,784 in B (+396,288, 4.3 %: the task,
  import, note and review cards). `mdedit-ai.exe` 2,265,088 and 2,270,208.
- **The PC.** Quiet during these runs (about 3 % load); another agent's two cargo processes
  existed but were idle. The owner's mdedit was open and was not touched.
- **Checks on B before measuring** (the scroll fix and audit 4's fixes together for the first
  time): `cargo fmt --all --check` clean; `cargo clippy --release --workspace --all-targets --
  -D warnings` clean; `cargo test --release --workspace`: 1,584 passed, 0 failed, 14 ignored.
- **Not measured.** The 100 MB file (as at 1.3.0); idle CPU beyond 6.5 s; anything on Linux or
  macOS; a launch with a session (the owner's settings are never used).
