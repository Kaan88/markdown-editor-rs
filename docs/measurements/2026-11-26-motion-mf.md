# M-F on Windows

## Launch and editing budgets

`tools/compare-builds.py` ran 31 alternating pairs of release builds `33e26d9`
(before the pin) and `ebd79cf` (all of M-F) on `fixtures/sample.rs`
at 1280 × 800 with `--no-session --behind --light` and scratch `MDEDIT_SETTINGS`.

| Measure | Before | After |
|---|---:|---:|
| First frame median, ms | 77.50 | 76.60 |
| First frame range, ms | 73.90–89.60 | 74.50–86.90 |
| Launches over 100 ms | 0/31 | 0/31 |
| First-frame compose median, ms | 11.79 | 11.76 |
| Idle private memory median, MiB | 27.10 | 27.00 |
| Keystroke p50 / p95, ms | 0.50 / 0.61 | 0.50 / 0.62 |
| Scroll p50 / p95, ms | 0.41 / 0.49 | 0.41 / 0.51 |

Paired first-frame median difference: −0.90 ms. Executables: 10,140,672 →
10,265,088 bytes (+124,416). The separate
[pin-only comparison](2026-11-26-motion-mf-pin.md) measured 79.50 → 78.50 ms
with no runs over budget.

For idle CPU, three five-second process samples per build started 650 ms after
the idle trace marker. All six reported 0.0 ms of CPU at the Windows process
counter's resolution. Both builds emitted 15 frame traces between the idle
marker and exit, not timed separately within the five-second sample.
Raw samples: `target/sol-mf-idle.log`.

## Restored-window path

W3 necessarily does placement work before window creation, but only for a
session with valid monitor-aware state. In another 31 alternating pairs,
`2cb1d08` and `ebd79cf` got the same generated 1280 × 800 session and placement,
with no restored tabs. First-frame medians were 43.9 → 43.9 ms (paired delta
+0.1 ms). Ranges were 40.8–67.7 → 41.4–54.4 ms; none exceeded 100 ms. Window
creation medians were 22.4 → 22.5 ms and hidden-first-present medians were both
38.1 ms. This is not a document-opening comparison.

A separate native smoke test restored a matching monitor to `(61, 101)` and
passed no position for a synthetic missing monitor; Windows placed that
window at `(26, 26)`. It did not unplug a physical monitor. W3 drew no new
state in the screenshot suite; differences against W2 were run timestamps,
fixture modification dates, and the worktree path shown in Open Recent.

Raw launch samples: `target/sol-mf-final-bench.log`, `target/sol-mf-w3-bench.log`.
Cold launch, the 100 MiB workload, active-transition timing, Linux and macOS
were not measured.
