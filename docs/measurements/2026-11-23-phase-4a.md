# Phase 4a (the folder import) against its base, before merging it

Measured 2026-11-23 on the Windows PC with `tools/compare-builds.py`, 7 interleaved runs, every
window `--behind`, a scratch settings file (`MDEDIT_SETTINGS`), `--no-session`. A is the base the
branch was cut from, `main` at `6b50a29` (worktree `md-wt\p4a-base`); B is `f/p4a` at `5c32001`,
which is that base with phase 4a merged with `main` at `6e6579f`.

**Verdict.** No change. The import adds a command, a card and a walk that runs only when the
command is used -- nothing on the launch path, no thread at start, no new dependency -- and the
figures agree with that: every delta is inside the two builds' own ranges, and the memory is the
same. `sample.rs` is over the first-frame budget in both builds already, by the same amount.

**The exe** grows from 9,201,152 to 9,298,944 bytes (+97,792, +0.95 %), which is the walk, the
plan, the card's drawing and their sentences; the 1.2.0 exe was 8,399,872 bytes, so this is not a
jump (rules in PLAN.md 48: the size is reported, not a gate).

**Not measured, and why.** What the card costs while it is open: typing and scrolling happen in
its list, not in a document, and neither `--type-steps` nor `--scroll-steps` drives a card, so no
figure exists for it; the walk's own time on a large folder was not timed with `--trace` either,
only by its tests (2,001 files, refused at the cap). The 100 MB figures include both builds, so a
change that only showed on a large file would still have moved them.
