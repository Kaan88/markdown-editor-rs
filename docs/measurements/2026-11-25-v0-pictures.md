## Claude API and OpenAI-compatible

Not tried. The brief allows a key that is already in the environment or a scratch config handed
over; there was neither (no `ANTHROPIC_API_KEY`, no `OPENAI_API_KEY`), and the owner's keys in
the credential store were not looked for, by rule. No local server (Ollama, LM Studio) was
running to try an OpenAI-compatible endpoint without a key.

The engine sends the documented shapes (plan section 6): for the Claude API, `content` a list of
`{"type":"image","source":{"type":"base64","media_type":…,"data":…}}` then the text; for
OpenAI-compatible, `content` a list of the text then `{"type":"image_url","image_url":{"url":"data:…;base64,…"}}`.
The tests check those shapes against a stub server. **What a real provider says to them is not
known** until a key is used once; until then neither is proven, and a text-only model's answer
(the `no_vision` mapping) is a guess from the usual wording.

## Claude Code

`claude -p --input-format stream-json` with one line on stdin, the engine's other flags as they
are for text runs (`--tools ""`, `--no-session-persistence`, `--system-prompt`), `--model haiku`
to keep it cheap. Started with Claude Code's own session variables (`CLAUDECODE`,
`CLAUDE_CODE_*`) removed, as mdedit starts it.

```
claude -p --input-format stream-json --output-format stream-json --verbose --tools "" \
  --no-session-persistence --system-prompt "You read pictures." --model haiku  < cc_in.jsonl
```

with `cc_in.jsonl` one line:

```json
{"type":"user","message":{"role":"user","content":[
  {"type":"image","source":{"type":"base64","media_type":"image/png","data":"iVBORw0…"}},
  {"type":"text","text":"What text is written in this picture? Answer with the text only."}]}}
```

Exit 0; the `result` line: `{"subtype":"success","is_error":false,"result":"V0 TEST 42"}`, one
turn. So `--tools ""` does not stop an image block: the picture travels inside the message, not
through a tool.

**Found on the way.** The `system` `init` line of that run listed about fifty tools although
`--tools ""` was given: every MCP server in the user's own Claude Code configuration (Claude
Docs, and others) was loaded into the child. `--tools ""` turns off the built-in tools only.
A second run with `--strict-mcp-config` added (and no `--mcp-config`) listed no tools and no MCP
servers and still answered `V0 TEST 42`. The engine's text runs have the same gap today; V1 adds
`--strict-mcp-config` to every Claude Code run, text and pictures, so a rewrite can reach no tool
at all (D-213).

**Decision for V1**: Claude Code is sent pictures, as stream-json image blocks on stdin, the text
block last.

## Codex

`codex exec --json --skip-git-repo-check --ephemeral --sandbox read-only --image <FILE> … -`,
the prompt on stdin. Every form tried got as far as `turn.started` and then
`{"type":"turn.failed","error":{"message":"You've hit your usage limit. … try again at
Nov 26th, 2026 6:04 PM."}}`. So nothing reached a model and nothing is known about whether it
reads the picture.

What was learnt about the command line, without the model:

- `--image <FILE> -`, `--image <FILE> -- -`, `--image A --image B -- -` and `--image A,B -- -`
  are all accepted: none is a usage error, and each read the prompt from stdin.
- **A file that does not exist is not refused** before the turn: `--image missing.png -` started
  the turn too. So the engine cannot rely on Codex to say a picture was not read; it checks its
  own files before it starts the program.
- The help gives `-i, --image <FILE>...`: several values, and (in Codex's source) split at commas.
  The engine therefore writes the pictures under names of its own (`1.jpg`, `2.png`) in a folder
  of its own, passes one `--image` per file, ends the options with `--` before the `-`, and refuses
  to start when the folder's path holds a comma.
- The user's `config.toml` produces an item of type `error` ("ignoring 1 unrecognized
  configuration setting") on every run. It is not a failure of the run: the engine's reader
  already ignores items that are not `agent_message`.

**Decision for V1**: the Codex sender is built in the form above and tested against a fake, but
**it is not proven**. Before the window offers Codex pictures (phase V3), one picture is sent
through it by hand after the allowance resets (2026-11-26 18:04), with:

```
codex exec --json --skip-git-repo-check --ephemeral --sandbox read-only --image <v0.png> -- - < prompt.txt
```

If it does not read "V0 TEST 42", Codex is offered no pictures (plan section 6).
