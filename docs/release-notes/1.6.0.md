mdedit 1.6.0: smoother menus and theme changes, a safer Markdown preview, and fixes to the AI task window.

## Motion

- **Menus fade in.** Menus, context menus and submenus fade in and settle into place as they
  open, in about a ninth of a second; closing is instant, and the word completion list appears at
  once as before.
- **Animations, in Settings › Appearance.** On by default. Off, nothing moves. With the system's
  animation effects off (Windows: Accessibility › Visual effects), nothing moves either.
- **Messages rise in and fade out.** A message at the bottom of the text now rises into place
  and fades away when its time is up. A message that updates (a count, a step) changes in place;
  confirmations such as "File path copied" stack, at most three, and the same one said again
  stays one — brought to the bottom, so the one you just triggered is the one in sight.
- **New waits for the lift.** When confirmations stack, the ones above lift out of the way
  before the new one rises in underneath.
- **Menu highlights fade, the command palette pops in, and notice bars slide into place.**
  Notices present on the first paint, a rename notice returning with its tab, word completion,
  and the language list stay instant. The crash notice is checked after the first paint, so
  it slides in just after launch when animations are on.
- **Settings switches slide and folder chevrons turn.**
- **Settings fades in when you open it.** Its card and dimmed background fade in together;
  changing pages and closing the dialog are still instant.
- **Light and dark themes crossfade.** The change takes 170 ms, including when the
  desktop changes while Theme is set to System. With a window backdrop, a very large
  window, or motion off, the theme still switches instantly. Choosing a theme from
  a menu or the command palette closes it immediately and still fades the theme.
- **Tooltip and title hover fixes.** Scrolling or middle-clicking a tab clears its tooltip
  immediately; hovering the active tab does not schedule an invisible fade.

## Navigation and window placement

- **Submenus follow the pointer and keyboard.** Escape or Left drops any pending hover
  change and closes the submenu that's actually on screen. Reopening a submenu shows
  current items and check marks.
- **The split preview has a scrollbar.** Click the track or drag the thumb to move
  through a long page without selecting its text.
- **Safer Markdown preview.** The preview refuses network image paths before checking for a
  file, and SVG images cannot read local files. Image and preview sizes are limited, and fixes
  to inline math and export prevent unusually slow processing. The preview normally uses only
  the helper shipped beside the editor, not a copy found in a parent folder or beside mdview.
- **Text rendering.** Font hinting adjusts glyphs vertically without snapping them horizontally.
- **Preview in mdview on Linux** finds a viewer installed under the same prefix, even off `PATH`.
- **Files and Functions have keyboard focus.** Use the pane's shortcut, move with the
  arrow keys, press Enter to open the row, or press Escape to go back to the editor.
- **Window placement follows the saved monitor.** If that monitor is no longer
  available, the operating system chooses where the window opens.

## The AI task window

- **A folder added to the window is walked whole.** Files in its subfolders, at any depth, are
  found and listed after the folder's own; a dot file or folder, `target` and `node_modules` are
  left out, and one add stops at 2,000 files, saying so in the window. The folder is read on its
  own thread — the window says "Reading <folder>…" meanwhile, and Esc stops it — and the cap
  counts only the files the window and a question hold not already. A folder of more than 200 new
  files is counted first and asked about before anything is read ("Add 1,240 files from
  Recipes?"); Add them reads and adds them, Leave them out reads none, and a folder that brings
  nothing new says so. A folder that cannot be read is named in the window, and so is one the walk
  stopped short of. A file added again is not one left out, and the plan waits while a question's
  files are still coming in.
- **Settings opened from the window comes to the front.** "Open AI settings" hides the AI task
  window until Settings closes, then brings it back as it was, with the connection, the limits
  and the saved prompts read again.
- **Esc no longer throws the setup away.** In a field with words in it, Esc leaves the field;
  then the window says once what closing would drop, and the next Esc closes it. Typing again
  goes back into the instruction. Cancel still closes at once.
- **Back on a rewrite's review and on a split's plan.** Back returns to the window with nothing
  written and the file still ticked.
- **The window reopens on the task it was last on**, and grows with a large window.
- **Its messages are in the window**, over the foot of its list. A successful picture paste
  also stacks as a confirmation toast.
- **Write notes' Files… lists pictures.**
- **"Show what is sent"** says whether anything was sent yet, and closing its tab (Close, Close
  others or Close all) brings the window back.
- **Write notes after a failed request** offers to go on only when there is something to go on
  with, so it can no longer get stuck, and "One note per picture instead" no longer changes How
  many or unticks the text file. The plan card counts the requests answered apart from those that
  failed.
- **Clearer words.** The button says what it does and how many files ("Make the plan for 4
  files", "Rewrite 1 file"), and is off, with the reason under it, when there is no file or no
  group. Files never sent are no longer called "not placed". The Options popover is drawn whole and
  on top, "Show what is sent" no longer overlaps Cancel, and the window reads whole at 520 px.

## Upgrading a Linux tarball installation

If you installed an older tarball, use the **new** `install.sh` with the same prefix to upgrade.
The editor now lives next to its preview helper in `lib/mdedit/`, with a link in `bin/`.
Use the new `uninstall.sh` if you later remove it; the old script does not remove the editor
from its new location.
