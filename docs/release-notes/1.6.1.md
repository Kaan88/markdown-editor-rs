mdedit 1.6.1: fixes for crashes and hangs in the Markdown preview and Settings, and a safer hand-over between windows.

This release moves mdedit onto the latest shared toolkit (`markdown-shared-rs` `48eedb8`). The
fixes below are in that shared code, which mdedit builds in.

## Crashes and hangs

- **Front matter with non-ASCII text in a large note** (over 16 KiB) no longer closes the app.
- **Alerts written out of order** in a Markdown file no longer close the preview.
- **List numbers in Roman numerals above 3999** no longer hang the preview.
- **Very deeply nested Markdown** is capped at 128 levels, and its text is kept.
- **Settings**: the arrow keys on an empty choice, and a progress meter narrower than a pixel, no
  longer close the app.
- **The update download** on Linux and macOS can no longer close the app.

## Fixes

- **Paste works again in secret fields**, such as an API key in Settings, and Ctrl+V handles large
  clipboards as before.
- **Copying files into the library** checks every link rewrite before it writes anything.
- **HTML pasted as Markdown** keeps backslashes in paths and escapes image descriptions.
- **Long previews** scroll correctly past the point where very tall pages used to go wrong, and
  pages with many dropped blocks lay out faster.
- A folder the app watches wakes it when watching fails, instead of going quiet.

## Opening a second window

When you open a file while mdedit is already running, the new copy now proves to the running one
that it belongs to the same user before it hands the file over. A window still running from
before the update does not accept files from 1.6.1: close it once after updating. mdview 1.2.1
makes the same change, so update both. With mdview 1.2.0 still open, "Preview in mdview" opens
the file there, but the viewer no longer follows the caret or the text you type, and mdedit says
to update mdview.

## Linux

The AppImage updates itself only when it is started as the AppImage, not when the program inside
it is run on its own. It keeps a small `.lck` file beside the AppImage while it updates.
