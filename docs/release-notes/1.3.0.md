mdedit 1.3.0: a notes library, so notes kept anywhere are one shortcut away.

## New

- **Split into notes.** "Split into notes…" in a tab's menu, the command palette, the AI menu and the Notes library submenu reads the document in front and shows the notes it would make, cut at its headings, before anything is written. Each note is a row with its title, its path and what would change; tick the ones you want, rename them, choose the group, and read a note's whole text beside it. Nothing is written until you press **Write the notes**, and the tab must be saved first, because the notes are made from the file on disk.

- **A write you can take back.** Writing a plan makes one folder per section and one file per note, each created where nothing of that name exists, and adds the notes to the library. Before anything else it writes a record of the whole plan in `.runs` in the library folder, and one line per finished step beside it. When it ends, the results panel says what was written and what was left out, and offers **Undo this run**: it asks first, with the numbers, takes the links out of the library, reads the library again, then removes only the files this run made, only while their contents are still exactly what it wrote, and never a note that a line in any library file still lists; then the group's list if the run made it and nothing but its heading is left, then the folders the run made while they are empty. A note you have changed since, and a line you have edited or moved, are kept and listed, each with its note. A file that was there before the run is never removed. Undo is refused when the document the notes were cut from has been deleted or changed, because the notes may then be the only copy; it never acts on a path in a record that is outside the library folder or the group's folder; and a record written by a later version of mdedit is listed as such and never deleted. **AI runs…** lists every run and does the same for any of them, with Show the notes.

- **New notes are named in lower case with hyphens.** A note called "Pasta Notes" is written as `pasta-notes.md`, whether it comes from a split or from "New note here…". Its title in the library is still "Pasta Notes", and files you already have keep their names.

- **The plan stays where you left it.** Escape keeps a plan, and the Notes pane's foot shows "Plan ready: 12 notes · Show · Drop" until you come back to it or drop it.

- **Notes library.** Keep a list of the notes you care about, wherever they live on disk, and open one by name. `Ctrl+Shift+N` lists every note, grouped, with its section beside it; type a few letters and press Enter. "Add this file to the notes library…" puts the open file under a heading you pick, and "Edit the notes library" opens the lists themselves. They are ordinary Markdown files in a `library` folder beside your settings — one file per group, a heading per section, a link or a path per note — so they can be written, read and shared by hand. Nothing is moved or copied, nothing is read at start, and a note whose file has gone is listed as missing instead of disappearing. The main menu has it all under "Notes library".

- **The notes library in the side pane.** `Ctrl+Shift+3`, or View › Notes library, puts the library in the left pane as a tree: group, section, subsection, note. Headings nest, so a library file is as deep a tree as you write it. Click a group or a section to fold it, a note to open it; a note whose file has gone keeps its place with a warning mark. The pane follows the files as you save them.
- **The notes library, worked properly.** A **Notes** button on the toolbar, and the side pane's head now says Files · Functions · Notes, so the three things the pane can show are one click apart and the folder button belongs to whichever is showing. The pane comes back with the face it had. Right-click anything in the library — a group, a section, a note, the empty space — for what you would expect: new group, new section, new note here, rename in place, move to another section or another group, find the file again when a note has moved, go to its line in the library file, remove it from the library. Taking a note out of the library leaves the note itself on disk; the one thing that does delete is "Delete this library file…" on a group, which removes that group's own list and says so, never the notes it lists. "Edit a library file…" now opens the one you are in rather than all of them. And the library folder is a setting, so it can live in OneDrive or beside your notes instead of next to the settings file.

- **The notes pane from the keyboard.** `Ctrl+Shift+3` now puts the keyboard in the pane: arrows move, Left and Right fold and unfold, Enter opens, `F2` renames in place, `Delete` takes a note out of the library, the Menu key opens the row menu, a letter jumps to the next row starting with it, and `Esc` gives the keyboard back to the text. Each row shows its note's folder, dimmed, so two notes called the same thing can be told apart, and "Show in the notes library" on a tab's menu finds the open file in the tree.

- **A folder for each group, so the library is not one flat heap.** A group of notes owns a folder, and a note you make under a heading is written in the folder that heading names: a note under Personal › Money › 2025 lands in `Personal/Money/2025/`, so the library reads the same in Explorer as it does in the pane. A group that has no folder yet gets one the first time mdedit writes a note in it, named after the group and recorded as one `home:` line in its library file, which older versions and mdview read straight past. **"New notes go in: … — Change…"** on a group points it at a folder you already keep, such as `D:\notes\work`, and clearing it puts things back. Nothing on disk is ever moved by any of this: existing notes stay exactly where they are.

- **Leave out the tab you were last on too.** A new switch under "Don't reopen tabs barely looked at" (Settings › Session): without it, the tab that was in front when you closed the window always comes back, however briefly you looked at it. With it, that tab follows the same rule as the rest, so a file you open, glance at and close the window on is not reopened. Pinned tabs and unsaved text always come back either way.

## Fixed

- **A library file saved in another window no longer freezes the pane.** The notes pane read the
  whole library again on the window's own thread whenever one of its files changed — 39 ms on a
  library of 2,000 notes, more as it grows. It reads on a worker thread now: the rows on screen
  and the keyboard's cursor stay where they are until the new ones are ready, and a read whose
  folder changed under it is thrown away rather than shown. A folder holding more library files
  than the reader keeps (now 512) says at the foot of the pane how many groups it shows.

- **Scrolling while editing on the page.** Visual editing (`Ctrl+E`) had no scrollbar: the page filled the window with nothing to show where you were and nothing to drag. It has one now, and the thumb keeps up with the pointer however fast you drag it. The scrollbars drawn inside an open block's box are gone — they measured the whole document and could never move, because the box always shows its own block; the page scrolls instead and the box moves with it.
- **Editing on the page stays on across tabs.** In `Ctrl+E`, switching to another tab dropped you into the text and the page side by side, and switching back did not bring the mode back. The mode belongs to the window now: another Markdown tab shows its page, with no block open, at the place that tab's text was; a file the page cannot show, such as a `.rs` file, ends the mode, and the preview pane goes back to what it was before — closed if `Ctrl+E` had opened it, left open if you had it open. Closing the tab the mode is on follows the next one, and a Markdown tab shown later does not turn the mode on by itself.
- Save As on a note the AI turned into Markdown now offers it a `.md` name instead of `.txt`; a new document is offered the extension of whatever language it is set to.
- **A note could be mistaken for a list of notes.** A note made with "New note here…" was written into the library folder itself, where every Markdown file is read as a group — so your notes appeared in the tree a second time as empty groups, and "Delete this library file…" would have deleted one, behind a question that promised the notes were not touched. New notes are written in their group's folder, notes already sitting in the library folder are no longer read as groups, and nothing that any library file lists as a note can be deleted that way.
- A note kept inside the library folder is now linked relative to it, so moving or syncing the library no longer breaks it.
- `Esc` on an AI result closes the review and **keeps** the result: the status bar says so, and "Show the last result" in the AI menu or the palette brings it back as it was. It used to be thrown away without a question.
- One rule now names every file and folder the library makes, so a title with `%` in it, or one called `CON`, is written under a name Windows and the library both read back as the same thing.

- **"Write the notes" says what is wrong before it writes anything, not after.** A new group whose
  file name is taken, a library full of library files or a group full of notes, a group's library
  file with unsaved changes, a document changed since the plan was made, and a section or a group
  called `C#` (whose heading does not read back) now stop the plan with the reason on the card,
  and nothing is written. The group's file is made before its notes, so a run that cannot finish
  leaves a group one can live with rather than notes with nothing listing them. "Split into notes…"
  reads the library where it opens, so it writes into the library folder and nowhere else, and a
  group's folder can no longer be the library folder itself. Two groups of one name now send the
  notes and their links to the same library file, and two titles that differ only in case get two
  files.
- **`--no-session` reads and writes nothing of yours.** Such a build has no library, no snippets
  and no saved prompts; give it `MDEDIT_SETTINGS` naming a scratch `settings.ini` when it needs
  them, and its library is that folder's `library`.
- **mdedit no longer closes itself when whatever was reading its messages has gone.** Started
  from a shell or a script that then closed its end, mdedit ended at its next line of output (a
  `--trace` line, or a failed update check or installation). Such a line is now dropped instead.
